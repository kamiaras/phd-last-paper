# Project context

## Goal

Fresh rewrite of the thesis chapter for publication.

## Source of truth

- **Active manuscript:** `fresh_rewrite.tex` — all editorial work goes here.

## Reference (read-only)

- **Baseline:** `Original/thesis-chapter-control.tex` — compare against this when rewriting.
- Do not edit files under `Original/` unless the user explicitly asks.

## Archive (recycle bin)

- **Path:** `archive/` — stale drafts, old copies, sent PDFs, and discarded variants.
- Do not edit, do not treat as the current manuscript, and do not copy from it into the rewrite unless the user asks to recover something specific.
- This folder is local-only and not tracked by git.

## Shared assets

- `ref.bib` — bibliography for the active rewrite.
- `images/` — figures used by the active rewrite (generated by `sim/` into `images/control/`).

## Simulation

- **Path:** `sim/` — experiment code for Section Experiments in `fresh_rewrite.tex`.
- **Figures:** write PNGs/PDFs to `images/control/` (subdirs `kappa0.1/`, `kappa0.4/`, etc.).
- Do not put simulation source in `images/` or `archive/`.

## Commit convention

- `rewrite:` — manuscript changes to `fresh_rewrite.tex`, `ref.bib`, or `images/`.
- `sim:` — simulation code under `sim/` or regenerated figures under `images/control/`.
- `chore:` — repo or meta changes (`.gitignore`, `AGENTS.md`, etc.).

## LaTeX

- Build artifacts are gitignored (`.aux`, `.log`, `.bbl`, etc.).
- PDF outputs (e.g. `fresh_rewrite.pdf`) are tracked.
- `fresh_rewrite.pdf` rebuilds automatically from `fresh_rewrite.tex` via `latexmk -pvc` (VS Code folder-open task) and the `.cursor/hooks` after-edit hook.

## Writing (always)

These rules apply to every change in `fresh_rewrite.tex`. Check the manuscript first; do not improvise a parallel language.

### Notation

- Do not invent new notation. Reuse the symbols already used in the paper, in the same roles.
- Stay consistent with existing style (fonts, subscripts, time indices, operator names).
- If a new symbol is unavoidable, pick one that is not already used, and keep its style aligned with the rest of the paper. Never overload an existing symbol.

### Terminology

- Do not invent terms. Use the names already used in the paper.
- If a concept already has a name in the manuscript (or in the baseline chapter), use that name. Do not introduce a synonym for variety.

### Language

- Write a STEM academic paper, not literature. Professional and academic, but not ornate.
- Prefer short, direct sentences. Avoid complicated wording when a simpler phrase is accurate.
- Use English where it helps the reader follow the argument (setup, hypotheses, what a step is doing). Do not replace algebra with prose.

### Mathematics

- Keep the mathematics algebra-focused. A mathematician should be able to follow a proof without filling in missing calculations.
- Show the algebra. Each displayed step should be simple to verify from the previous line (one substitution, one estimate, one cited identity).
- Do not skip “routine” algebra. Do not write “it is easy to see” in place of a step.
- Use English only when it is needed to state assumptions, point to a previous result, or say why the next algebraic step is valid.
